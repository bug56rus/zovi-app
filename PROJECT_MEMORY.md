# 🚀 Project Memory & Dev Log: "Partiful for Russia"

## 📌 Главная идея и архитектура
Мы создаем MVP приложения для организации приватных мероприятий. 
**Главная фишка:** Полная анонимность. Мы НЕ собираем персональные данные (ФИО, телефоны). Гости подтверждают участие по одноразовым ссылкам (magic links). Сервер хранит только токены и статусы (going/maybe/not_going), а имена гостей хранятся ТОЛЬКО на устройстве организатора.

**Технический стек:**
- **Монорепозиторий:** npm workspaces.
- **Бэкенд:** Node.js + Fastify (TypeScript).
- **База данных:** PostgreSQL + Drizzle ORM.
- **Фронтенд (Сайт гостя):** Next.js (App Router, SSR).
- **Мобильное приложение (Организатор):** React Native + Expo (в планах).

## 📂 Структура проекта
- `apps/api` — сервер Fastify (порт 3000).
- `apps/web` — сайт Next.js (порт 3001).
- `packages/db` — Drizzle схема и миграции.
- `packages/shared` — общие типы.

## 🚦 Как запустить локально (для нового ИИ)
1. Убедитесь, что запущен PostgreSQL (через `brew services start postgresql@16`).
2. База данных создана: `createdb -O postgres eventapp`.
3. В первом терминале: `npm run dev --workspace=apps/api` (API на 3000).
4. Во втором терминале: `npm run dev --workspace=apps/web` (Сайт на 3001).
5. Тестовое приглашение: `http://localhost:3001/i/9493665a`

📅 10.11.26 (день 1) - 3 часа

🏗️ **Каркас и База:** Создан монорепозиторий. Установлен PostgreSQL через Homebrew. Настроен Drizzle ORM. Создана схема БД с двумя таблицами (`events`, `invites`). Сгенерирована и применена миграция. Решена проблема с частичным уникальным индексом `WHERE magic_token IS NOT NULL` (для предотвращения дубликатов RSVP).
⚙️ **Бэкенд (Fastify):** Написан API. Эндпоинты: `POST /events` (создание), `POST /events/:id/invites` (генерация ссылок с защитой по `X-Admin-Token`), `GET /i/:token` (информация о событии для гостя), `POST /i/:token/rsvp` (обработка ответа с выдачей httpOnly cookie).
🖥️ **Фронтенд (Next.js):** Сверстана SSR-страница `/i/[inviteToken]`. Подключен клиентский компонент `RsvpButtons`, который отправляет fetch-запросы на API. Проверен полный цикл: создание события -> генерация инвайта -> открытие страницы -> нажатие кнопки -> запись в БД.
🛠️ **Проблемы и решения:** Bionic (Qwen 9B) не справлялся с написанием кода для Drizzle (путал SQLite и PostgreSQL, выдавал несуществующие версии). Решение: перешли на `gpt-oss-20b-OptiQ-4bit`, а критически важные файлы (схемы, сервер) создали вручную через терминал, чтобы избежать галлюцинаций ИИ.
🖥️ **Панель организатора (Web):** Создана страница `/admin` для создания события (сохранение `adminToken` в localStorage). Реализована панель управления `/admin/[eventId]`: отображение статистики (Придут/Не уверены/Не придут), генерация новых инвайтов (POST запрос).
📱 **Шаринг для iPhone:** Внедрена функция `navigator.share()` для Safari. Теперь при нажатии «Поделиться» открывается системное меню iOS для отправки в MAX/Telegram/WhatsApp. Добавлена отдельная кнопка «Копировать» (копирует только чистую ссылку).
🛡️ **Защита от ошибок:** Добавлен `cleanToken` на странице гостя. Если пользователь случайно скопирует текст вместе со ссылкой (например, "Приглашаю тебя на... http://..."), страница автоматически отрежет лишний текст и откроет правильное приглашение.
🔗 **Связка:** Проверен полный цикл: Организатор создает событие -> генерирует ссылку -> отправляет гостю -> гость нажимает кнопку -> статистика на панели организатора обновляется (после F5).
